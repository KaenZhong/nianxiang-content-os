# 念响开发维护 · 开发经验

本页收录截至2026-10-16在本次维护协作中出现的真实经验。历史事实来自当时工具核验、用户反馈及测试报告；它们不是当前运行状态。用户私人正文和完整日志不复制到这里。

## 1. 发布完成要验证用户实际取得的包

- 触发与症状：main已更新而Tags仍旧；随后有Tag但尚无标准Release附件。用户无法方便安装或查看更新变化。
- 原因与证据：main、Tag与Release是不同对象；beta.14的固定Tag曾先于完整Release。beta.18又因旧Skill将“更新GitHub”限定为源码而提前收口；用户随后明确约定“推送GitHub”就是完整发布。问题包括旧规则与用户实际交付目标不一致，不能只归因为漏执行清单。
- 处理：以用户确认的最终交付目标解释动作词。念响项目“推送/更新GitHub”沿用完整发行授权，连续完成源码、Tag、Release、标准包和下载验证；明确“仅推源码”才缩小范围。替换旧的源码默认规则及验收示例，不叠加互相冲突的条款。
- 范围：beta.14、beta.18公开下载及摘要当时已验证；新范围约定来自用户明确指令。修订后触发仍待独立Agent复测，不证明其他平台安装、模型执行或新会话持久性。

## 2. 同名草稿会掩盖已公开发行

- 触发与症状：用户截图beta.12页面显示Draft，与此前公开下载通过看似矛盾。
- 原因与证据：GitHub发行列表实际有两份同tag记录，一份公开且三个附件完整，另一份草稿无附件。不是公开版被撤回。
- 处理：先列出全部发行及draft/asset状态；结果不明先查询再重试创建。清理重复草稿前核对其内容、附件及授权，不删除正常公开版或已发行Tag。
- 范围：当时重复空草稿已清理、公开版保留。不能仅凭截图判断全站发布状态。

## 3. 标签源码包与用户安装包不同

- 触发与症状：用户下载标签源码ZIP看到开发README与AGENTS.md，不知道该导入哪层。
- 原因：GitHub自动归档整个仓库，根目录包含维护文件；Skill在子目录。
- 处理：提供仅完整Skill的标准Asset，校验与LICENSE另附；不删除开发源文件，不删除Skill自身依赖文件。指南明确标准ZIP与Source code ZIP的区别。beta.18用户继续询问Assets五个文件的用途，说明仅提供文件仍不足；交付直接写下载哪三个、各自做什么、交给Agent核验安装，减少人类自行判断。
- 范围：beta.12、beta.14标准附件已验包；不意味着GitHub自动源码ZIP已改变结构。

## 4. 云端会话内更新不证明以后生效

- 触发与症状：豆包报告当前入口更新为beta.10，新会话又读到beta.9。
- 原因与证据：测试报告记录平台按会话重装运行目录、旧平台受管源仍被加载。此为报告证据，维护者未直接读取云端文件全貌。
- 处理：磁盘、对话读取、新会话和平台受管源分别核验；不能凭active或“新开对话”承诺长期生效，不用重复apply代替源更新。
- 范围：称呼缓存恢复和部分真实读回曾通过；跨环境、重启与完整持久旅程仍需各自验证。

## 5. 符号链接先解析，底层限制保留

- 触发与症状：云端常规Skill路径status/apply返回invalid_path。
- 原因与证据：测试报告指出.user_skills指向/runtime/user_skills；更新器拒绝重定向路径。本机隔离预检验证解析后可识别安装而直接传重定向路径仍被拒绝。
- 处理：上层展示原路径与真实路径、核对实际入口及私人目录分离，再使用真实目标；切换前核对解析未变。不直接放宽底层或包内符号链接限制。
- 范围：本机预检通过与云端报告分别成立，不等于所有文件系统已测试。

## 6. 工具兼容修复要正式落源

- 触发与症状：豆包CLI不提供auth子命令；原身份检查阻塞，测试Agent临时修改两处公共脚本。
- 原因与证据：原失败、脱敏接口结构和修改摘要见历史通讯记录；曾缺完整备份，不能按原版跨平台通过。报告中的beta.10兼容试验有双路径实现；不能推定后续所有版本都保留。
- 处理：取实际help和最小响应，核验当前用户身份与账号一致性，在开发源实现并落新版；清单仍旧而公共文件已改应视作冲突，不重做安装清单绕过。是否进入当前源码用git和文件核验。
- 范围：当时临时环境的保存及恢复证据限定在修改环境，不扩大为官方原包通过。

## 7. 用户指南应让Agent承担技术检查

- 触发与症状：提示词绑定某版本，发版后过期；用户不理解Pre-release或受管源等术语。
- 处理：内测用户使用指南使用通用Releases入口，包含公开Pre-release，要求Agent核验实际版本、标准包和平台能力；人类步骤先安装、小任务、按需更新验证、群内反馈。必要手动操作一次一步，技术细节交给Agent。
- 证据与范围：指南重命名、步骤与提示词修改后已回读，代码块自动换行通过；未因此宣布跨平台上手体验全部通过。

## 8. 飞书发消息和编辑公告权限独立

- 触发与症状：群消息发送成功，公告读取仍因缺scope失败。
- 原因与证据：用户及应用身份分别核验，公告read/write权限独立于消息发送；用户完成最小权限授权后，空公告写入规则并读回，模板wrap=true。
- 处理：遇权限问题查实际身份与scope，按可用能力发起最小授权；已获写入业务授权不反复确认同一内容。群中Agent消息不授权自主回复、修复或持续监听。
- 范围：特定群当时公告写读通过，不保证其他群或新环境权限相同。

## 9. 结构升级说明不能被功能亮点掩盖

- 触发与症状：beta.18同时包含内容范式能力和私人配置schema 5，单写功能亮点不足以指导旧用户更新。
- 原因与证据：配置映射和知识结构变化有独立升级入口；当时Release已单列兼容说明，说明核心更新不自动升级私人配置、核心回退不回滚私人配置。
- 处理：发行前比较上一公开安装版的schema、知识结构及迁移要求，中文说明明确旧用户操作、资料处理、回退影响与未验证项；只给公共发行授权不能自动执行私人迁移。
- 范围：172项本地测试、标准包及公开下载在beta.18发行时通过；真实用户知识库升级及跨平台持久性不据此宣布通过。
