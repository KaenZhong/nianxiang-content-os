# 念响AI · 内容OS

完整名称为“念响AI · 内容OS”，日常简称“念响内容OS”。

念响AI是面向个人IP与一人公司的内容操作系统；阿响是系统中的内容Agent，也是你的内容合伙人。先通过经你确认的个人内容知识理解你，再一起判断素材、选择切口、写朋友圈和口播。一次采用、一篇好稿与真实发表分别记录；保存和长期记忆由你决定。

当前为 **v0.1.0-beta.9 · 内测版**。已实现个人知识/协作规则、任务恢复、复盘衔接、受控更新及旧名显式迁移。真实飞书与其他平台完整使用仍待验证。[三平台接入说明](docs/platform-setup.md)提供安装与能力检查。许可证与GitHub发布位置待落实；本包供本地内测，不代表正式开源发布。

## 第一次使用

导入Skill时，让安装Agent读取[安装与私人目录初始化](references/system/installation.md)。它会先扫描已有私人目录，告诉你完整路径和保存内容；首次创建或接管需你确认，随后立即创建或复用并回读。云端还会核对持久位置；没有文件能力时明确说明目录尚未初始化。已有有效记录直接复用。

让你的Agent读取[SKILL.md](SKILL.md)，说：

> 阿响，帮我建立个人内容知识库。我想先用下面这份素材写一条朋友圈。

阿响会先检查当前工具与知识库位置，带你确认核心个人知识；不要求一次填完全部页面。已有库先复用，不重复创建。想先试写，也可以只提供素材，明确本次没有长期记忆。

- 想聊素材：`阿响，这段经历值得讲什么？`
- 想挑选题：`挖掘选题，我选好再保存。`
- 想出稿：`写朋友圈，把这段经历写成稿。`
- 想转口播：`做口播，用这篇未发表的稿。`
- 想保存：明确指哪篇作品、哪个版本和保存位置。

## 关键决策选择

选题、创作方向和沉淀候选需要你决定时，阿响先给推荐及取舍，再使用当前平台提供的原生选择卡；没有该能力时用文字选项。已明确的要求直接推进，选择不会自动成为长期偏好。[交互协议](references/system/interaction.md)说明等待、答案匹配与授权边界；当前平台指运行阿响的工具，例如Codex、WorkBuddy或豆包工作；是否能显示选择卡，以本次会话实际可用的提问工具为准。

## 个人资料与连接

[分批建库](references/knowledge/bootstrap.md)负责起步；[连接说明](references/knowledge/connection.md)负责账号选择、读取、授权保存与恢复。[数据归属](references/system/data-ownership.md)约定飞书是私人长期知识唯一权威，本地运行配置档放在Skill目录之外；旧私人资料按[个人源协议](references/knowledge/personal.md)显式预览、授权迁移；公开包只有通用方法与占位示例。换Agent后仍须确认同一账号和空间，不把旧快照叫最新。

有Python与已认证lark-cli时可运行标准库管理脚本；有原生飞书工具时按同一业务契约操作；工具不足仍能基于本轮材料共创。当前实机能力按平台分别验证，不预先宣称三平台均可用。

## 更新与私人规则

[受控更新](references/maintenance/releases.md)支持已信任且明确指定的本地公共包；验包、公共改动冲突、备份、切换、回退与中断恢复共用一个管理入口。个人资料与确认规则在包外保留。当前官方发行源未配置，检查更新返回`not_configured`。有完整发行清单的旧名安装可显式预览名称迁移并恢复；无清单的旧安装须先保留，单独导入新公共包。私人资料归位另行预览、绑定具体内容授权并逐类回读，原件保留；本包制作未迁移真实个人库。
