# 念响OS · 内容工作台共创

## 入口与适用范围

用户说“放进工作台”“把这篇放进工作台”“用工作台继续改”等，承接当前图文稿，读取本篇方法。工作台是图文正文、标题、配图的可选共创载体，不局限朋友圈，不增加公众号写法模块。已有完整稿直接载入；多篇指向不清只确认哪篇；只有选题时说明缺少初稿，按共创工作流取得出稿授权，不把打开工作台当成出稿授权。单篇、多篇与每日推荐统一使用下文内容工作台流程，不再交付独立单篇页面；尚未出稿仍遵守共创授权。

具备文件和Python能力时使用包内固定模板与生成脚本，不重新生成UI。无图片也可进入，配图面板默认收起，展开后显示占位；配图、标题、正文均支持独立收起展开，折叠不丢失编辑值。无文件、脚本或页面展示能力时继续对话或文档共创，如实说明，不阻塞内容交付。

打开时优先使用Agent内置浏览器，先复用同一工作台的已有标签页；内置浏览器不可用或用户明确指定时使用外部浏览器。完整HTML在内置浏览器打开与嵌入聊天中的交互组件是不同载体，不为接入聊天而重做或压缩原工作台。不同浏览器的草稿不假定互通；换浏览器前先交回或导出未交接的修改。

工作台承载正文、标题、配图的编辑与选择；用户的想法、修改要求和阿响的判断留在聊天中沟通。沿用“复制给阿响”入口，不为交接另加修改要求输入或独立共创板块。点击交接只提供当前稿，不自动发起改稿、定稿、入库或发布。

## 数据归属

唯一交付模板位于 `assets/content-workbench/index.html`；`assets/graphic-workbench/` 是内部单篇编辑组件与历史格式兼容资源，不作为另一工作台入口。通用品牌、slogan、阿响图标及开发者信息随模板保留；真实作品、图片、私人链接和浏览器草稿不进入公共包。

每批使用包外独立私人任务目录，沿用用户已确认的任务位置；首次创建或接管私人根仍按安装协议确认。目录内 `content.json` 是本次交接的内容源，`images/` 保存图片，`index.html` 为保留文件名的展示产物，可从模板重建；默认index.html是自包含交付页，内联样式、数据、脚本与图片，单独复制该HTML即可携带当前内容。不要放在公共Skill或覆盖已有无关文件。飞书仍是长期知识与作品记录的权威；本地内容包是未入库的当前工作稿，不自动覆盖已发布版。

## 内容包与生成

最小数据结构如下，示例仅说明字段，不作为真实用户内容：

```json
{
  "id": "stable-work-id",
  "body": "",
  "titles": [{"text": "候选标题", "type": "方法型"}],
  "selectedTitle": 0,
  "images": [],
  "creation": {
    "topic": {"title": "当前选题", "angle": "一句话切口", "valueBasis": "价值依据", "sourceClues": "来源线索", "sources": []},
    "topicMap": null,
    "draftBatch": null
  }
}
```

空标题列表时 `selectedTitle=-1`；有标题时为选中项从0开始的索引。标题类型按实际阅读价值标注，不强行凑类型；字数和语义检查沿用当前渠道方法。图片项为 `{"id":"cover","label":"封面","path":"images/cover.png"}`，清单顺序就是展示顺序，id稳定且唯一，路径必须在任务目录images/内。仅支持PNG/JPEG/WebP/GIF本地图片。选题地图和批量初稿为 `{"title":"真实文档名称","url":"https://..."}`，保留定位到本篇的锚点，缺失设null；不得用内容范式冒充原选题或原初稿来源，不猜链接。

从内容中台恢复时核验作品、关联选题及对应文档：正文按用户指定版本，未指定则已发布作品使用已发布版，其他按有效当前版；标题保留真实选定项，新增候选明确交代。图片按确认的终选清单，不把附加截图当定稿图。导航使用原选题字段和原记录链接，不以事后范式重写历史选题依据。私人来源线索只在本地展示，不自动进入对外文案。

```bash
python3 -B scripts/content_workbench.py --content /用户已确认任务目录/content.json
```

脚本统一生成自包含index.html，单篇对象或包含works数组的批次均可直接载入。模板更新不改写content.json；同批内容保持浏览器草稿标识。旧graphic_workbench.py命令保留历史交回格式校验与导入兼容，输出同一内容工作台，不再输出独立单篇体验。交付实际页面绝对路径；工具允许时打开，受限时给可点击文件入口。图片未变不重复制作。

## 单文件交付与分享验证

交付默认使用自包含index.html。分享托管仅收录一个HTML时，不交付依赖相对资源的多文件页面；分享前核对HTML已包含样式、数据、脚本和所有图片，没有外部运行资源依赖。图片内嵌仅用于展示和下载，复制给阿响及导出仍保留content.json内的相对路径和作品版本，不把base64数据塞进交接内容。

仅更新交付方式、嵌入资源和模板不改变内容字段与版本。完整私有content.json及原图仍留本地供后续改稿，用户无需在公开页面看到实现细节。自包含页携带正文、图片和导航链接；分享或公开上传仍按本次实际授权范围执行，不因生成而自动上传。

通过用户已指定且可用的分享平台交付时，实际打开分享结果检查正文、标题、图片、折叠与复制交接。平台若过滤脚本、data图片或限制文件大小，自包含也不能保证可用；如实说明并提供本地完整页，不宣称所有分享平台兼容。未取得真实分享工具时交付本地单文件，并明确平台复测未完成。页面显示空模板时先检查分享页资源/脚本执行，不误报数据丢失，不清除用户草稿来掩盖加载问题。

## 页面反馈与版本保护

浏览器草稿独立保存，阿响不能假称已自动收到页面修改。用户在页面编辑后点“复制给阿响”，粘贴回对话并说明要求；先承接用户修改，再继续创作。完整交接包含work_id、base_revision、正文、标题候选/类型、选定标题与图片顺序。

当前环境已有并验证过页面保存、Agent读取通道时，优先使用轻量交接：先把点击时的完整快照保存到已确认的包外私人任务目录并确认成功，剪贴板只放简短口令和能唯一定位该快照的文件路径或引用。阿响收到后读取指定快照，核对作品和版本，按用户在聊天中的实际要求继续；不能只读全局“最新稿”、猜测正文或擅自补修改要求。同稿重复交接可复用已核验快照，新稿保留独立版本；仅有请求编号而没有可解析的定位依据不算完整交接。

轻量交接不等于自动唤起聊天；当前公共模板仍复制完整交接数据，未内置测试用本地通讯桥。不可因读过本规则就宣称按钮已升级。无保存或读取通道时沿用完整数据复制或导出交回；保存失败不能提示“已交接”，复制失败但快照已保存时提供可手动复制的短指令。未实际传回的浏览器修改保持未知，不通过界面自动操作冒充正式接口已连通。

当前工作台交回的是包含works数组的完整快照，按每篇work_id、base_revision核对原批次后，在对话按授权合并；不直接传给旧格式导入器。仅处理旧单篇页面交回的历史selection格式时，可先保存在私人任务目录，再执行：

```bash
python3 -B scripts/graphic_workbench.py --content /任务目录/content.json --import-selection /任务目录/selection.json
```

仅当作品标识与原内容版本匹配才导入；版本不符停止导入，在对话比较合并，禁止强制覆盖。当前内容工作台按批次及原内容版本恢复本机草稿；源内容变化会使用独立批次存储，不自动合并旧稿。重新生成前先交回或备份未交接修改，不把旧单篇组件的冲突弹窗当作整批更新保护。浏览器存储不可靠时及时交回或导出，不假称已写回content.json。生成脚本不提供并发写锁，同一批次串行更新。

若环境提供结果写回能力，先展示可审阅的修改，采用前再次核对作品、交接快照与当前稿；提交后继续编辑产生的差异不能被旧结果直接覆盖。不具备写回能力时在对话交付，不假称页面已自动更新。

页面上的选中、编辑、复制、导出均不等于定稿、入库或发布。用户确认定稿后标明当前采用版本；按具体入库授权用作品契约查重、写入、回读，发布后仅按真实发布事实回填；沉淀仍走原流程。工作台不直接持有飞书凭证或调用远端写接口。

## 验收

核对空图占位、单/多图、标题类型与字数、字号、整卡选中、交接导出，确认模板不带私人示例；默认单文件脱离同目录资源后仍可载入，内联脚本在DOM就绪后执行。验证同版草稿恢复、源变化后独立批次保存、跨作品/过期交接拒绝，以及来源链接保留。静态与合成测试不代表多端实机及完整飞书保存闭环已验证。

采用轻量交接的环境另验：快照保存成功才复制短指令、指定引用可读取且版本匹配、重复点击不重复造同稿、失败分支不误报、内置浏览器可打开完整页及复用标签。页面提交、Agent读取、结果返回、用户采用与自动唤起聊天分别验收；本机实验不能代替公共模板或其他宿主的实现与实测。


## 统一内容工作台

单篇及多篇已有稿件统一使用`assets/content-workbench/index.html`及`scripts/content_workbench.py`；不重做UI，不把单篇入口强套成逐篇重新打开。包外`content.json`格式为`{"date":"用户实际日期或批次名","works":[单篇内容对象]}`。每篇沿用稳定id、body、titles、selectedTitle、images、creation字段，可加name、slot及source定位信息；未选标题允许selectedTitle=-1。来源、原版本及初稿待校准/可发布/已发布状态必须据实际记录填写，配图不齐不编造。

运行：`python3 -B <Skill目录>/scripts/content_workbench.py --content <包外content.json>`。输出同目录自包含index.html，真实稿件不进入公共包。不改输入原文或飞书状态；相同批次可恢复本机编辑，源内容变化使用独立批次存储，旧草稿通过原页备份或交回后合并，不静默覆盖。固定模板只供承接已有稿件，未载入时提示等待，不给手动添加稿件按钮。

桌面保留稿件侧栏与编辑双栏；移动端固定选题上方的当前稿件及切换操作，正文、标题、配图从上到下排列，保留页边与卡片内留白，选题上下间隔与卡片间距一致。手机按钮紧凑，正文按字号控件实际调整，不用强制字号覆盖；底部不重复放复制正文。桌面布局不随手机调整改变。

用户在工作台修改后仍通过单篇/批量交回完整快照，work_id与base_revision须与原数据核对，过期版本回对话合并，不自动回写。复制、编辑与候选标题选择不代表定稿、入库或真实发布。实际保存沿作品契约。每日推荐消息及宿主任务衔接见[定时协作引导](../system/scheduled-tasks.md)。

侧边栏不提供选择框，点击稿件即可切换。交回弹窗仅承接当前正在编辑的作品，复制给阿响及弹窗内导出均只包含当前篇；弹窗右上角叉号关闭。导出全部稿件及备份全部稿件覆盖整个批次，不再依赖勾选。移动端稿件列表入口与上一篇、下一篇在同一行；不显示正文复制按钮，正文可直接选择复制。桌面正文卡保留原复制操作。
