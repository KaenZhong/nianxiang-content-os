# 念响OS · 图文工作台共创

## 入口与适用范围

用户说“放进工作台”“把这篇放进工作台”“用工作台继续改”等，承接当前图文稿，读取本篇方法。工作台是图文正文、标题、配图的可选共创载体，不局限朋友圈，不增加公众号写法模块。已有完整稿直接载入；多篇指向不清只确认哪篇；只有选题时说明缺少初稿，按共创工作流取得出稿授权，不把打开工作台当成出稿授权。批量初稿仍先按既有批量流程交付，选中单篇再载入。

具备文件和Python能力时使用包内固定模板与生成脚本，不重新生成UI。无图片也可进入，配图面板默认收起，展开后显示占位；配图、标题、正文均支持独立收起展开，折叠不丢失编辑值。无文件、脚本或页面展示能力时继续对话或文档共创，如实说明，不阻塞内容交付。

## 数据归属

公共模板位于 `assets/graphic-workbench/`，包括HTML、CSS与交互代码。通用品牌、slogan、阿响图标及开发者信息随模板保留；真实作品、图片、私人链接和浏览器草稿不进入公共包。

每篇使用包外独立私人任务目录，沿用用户已确认的任务位置；首次创建或接管私人根仍按安装协议确认。目录内 `content.json` 是本次交接的内容源，`images/` 保存图片，`index.html/style.css/app.js/data.js` 为保留文件名的展示产物，可从模板重建；默认index.html是自包含交付页，内联样式、数据、脚本与图片，单独复制该HTML即可携带当前内容。不要放在公共Skill或覆盖已有无关文件。飞书仍是长期知识与作品记录的权威；本地内容包是未入库的当前工作稿，不自动覆盖已发布版。

## 内容包与生成

最小数据结构如下，示例仅说明字段，不作为真实用户内容：

```json
{
  "id": "stable-work-id",
  "body": "",
  "titles": [{"text": "候选标题", "type": "方法型"}],
  "selectedTitle": 0,
  "images": [],
  "creation": {
    "topic": {"title": "当前选题", "angle": "一句话切口", "valueBasis": "价值依据", "sourceClues": "来源线索", "sources": []},
    "topicMap": null,
    "draftBatch": null
  }
}
```

空标题列表时 `selectedTitle=-1`；有标题时为选中项从0开始的索引。标题类型按实际阅读价值标注，不强行凑类型；字数和语义检查沿用当前渠道方法。图片项为 `{"id":"cover","label":"封面","path":"images/cover.png"}`，清单顺序就是展示顺序，id稳定且唯一，路径必须在任务目录images/内。仅支持PNG/JPEG/WebP/GIF本地图片。选题地图和批量初稿为 `{"title":"真实文档名称","url":"https://..."}`，保留定位到本篇的锚点，缺失设null；不得用内容范式冒充原选题或原初稿来源，不猜链接。

从内容中台恢复时核验作品、关联选题及对应文档：正文按用户指定版本，未指定则已发布作品使用已发布版，其他按有效当前版；标题保留真实选定项，新增候选明确交代。图片按确认的终选清单，不把附加截图当定稿图。导航使用原选题字段和原记录链接，不以事后范式重写历史选题依据。私人来源线索只在本地展示，不自动进入对外文案。

```bash
python3 -B scripts/graphic_workbench.py --content /用户已确认任务目录/content.json
```

脚本默认生成自包含index.html，也可显式加 `--self-contained`；脚本放在页面DOM之后执行，内联脚本不能依赖defer。只有明确需要本地多文件模式时用 `--multi-file`，其HTML依赖同目录样式、脚本与images，不能单独上传分享。脚本生成内容版本摘要，更新固定模板与展示数据。`data.js` 由JSON派生以支持file页面直接打开，不能手改两套数据。改正文、标题、图片或关联信息时更新同一content.json并重新生成；同篇id不变，图片id稳定。只更新模板样式或交互时重新生成展示文件，不改写内容字段；内容版本摘要保持不变，避免仅因界面更新触发草稿冲突。交付实际页面绝对路径；工具允许时打开，受限时给可点击文件入口，不绕过访问限制。图片未变不重复制作。

## 单文件交付与分享验证

交付默认使用自包含index.html。分享托管仅收录一个HTML时，不交付依赖相对资源的多文件页面；分享前核对HTML已包含样式、数据、脚本和所有图片，没有外部运行资源依赖。图片内嵌仅用于展示和下载，复制给阿响及导出仍保留content.json内的相对路径和作品版本，不把base64数据塞进交接内容。

仅更新交付方式、嵌入资源和模板不改变内容字段与版本。完整私有content.json及原图仍留本地供后续改稿，用户无需在公开页面看到实现细节。自包含页携带正文、图片和导航链接；分享或公开上传仍按本次实际授权范围执行，不因生成而自动上传。

通过用户已指定且可用的分享平台交付时，实际打开分享结果检查正文、标题、图片、折叠与复制交接。平台若过滤脚本、data图片或限制文件大小，自包含也不能保证可用；如实说明并提供本地完整页，不宣称所有分享平台兼容。未取得真实分享工具时交付本地单文件，并明确平台复测未完成。页面显示空模板时先检查分享页资源/脚本执行，不误报数据丢失，不清除用户草稿来掩盖加载问题。

## 页面反馈与版本保护

浏览器草稿独立保存，阿响不能假称已自动收到页面修改。用户在页面编辑后点“复制给阿响”，粘贴回对话并说明要求；先承接用户修改，再继续创作。交接包含work_id、base_revision、正文、标题候选/类型、选定标题与图片顺序。

交回JSON可先保存在私人任务目录，再执行：

```bash
python3 -B scripts/graphic_workbench.py --content /任务目录/content.json --import-selection /任务目录/selection.json
```

仅当作品标识与原内容版本匹配才导入；版本不符停止导入，比较用户交回稿和当前稿，在对话合并，禁止强制覆盖。浏览器同版恢复草稿，新版遇到未交回修改时弹出选择，使用新版前触发本机草稿备份下载；继续旧草稿保留旧base_revision，后续交回必须合并。浏览器存储不可靠或备份下载被限制时，先复制交回/手动导出再切换，不假称已写回content.json。生成中断后可从content.json重新运行；生成脚本不提供并发写锁，同一作品串行更新。

页面上的选中、编辑、复制、导出均不等于定稿、入库或发布。用户确认定稿后标明当前采用版本；按具体入库授权用作品契约查重、写入、回读，发布后仅按真实发布事实回填；沉淀仍走原流程。工作台不直接持有飞书凭证或调用远端写接口。

## 验收

核对空图占位、单/多图、标题类型与字数、字号、整卡选中、交接导出，确认模板不带私人示例；默认单文件脱离同目录资源后仍可载入，内联脚本在DOM就绪后执行。验证同版草稿恢复、新版冲突提示、跨作品/过期交接拒绝，以及来源链接保留。静态与合成测试不代表多端实机及完整飞书保存闭环已验证。
