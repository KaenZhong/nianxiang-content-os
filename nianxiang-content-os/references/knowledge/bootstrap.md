# 念响AI · 分批建库与首次成功

## 从用户目标进入

第一次使用时说明阿响能做什么，并询问用户希望先完成的内容任务、昵称与记忆范围。已有任务先接素材，不以建库表单阻断。希望持续理解用户时，再引导选择飞书位置与可用工具；未知事实留空，Agent推断标为候选。

## 检查位置和骨架

工具须能核验当前用户身份、读取Wiki/Docx/Base并返回真实对象ID；写入权限单独确认。用户选择知识空间后，先展示将复用或创建的具体对象。公共[结构清单](../../assets/templates/knowledge-structure.json)保持四组知识职责、12映射和四表。已有库精确发现并复用，缺项才创建；重名或父子关系异常先停止，不另建一整套。

Python路径先按[连接说明](connection.md)创建包外配置档，绑定真实账号与选定空间。再从Skill根运行：

```bash
python3 scripts/manage.py --data-dir '<私人根>' --profile '<UUID>' bootstrap plan
python3 scripts/manage.py --data-dir '<私人根>' --profile '<UUID>' bootstrap apply --plan '<预览返回的私人计划路径>' --consent '<用户对本空间本骨架的明确授权>'
```

plan是只读远端预览，并在私人目录记录计划。apply逐对象创建与回查，保留中断状态；同一计划续建先查已创建节点与表，不因超时重复创建。曾尝试而无法确认的对象保持uncertain，人工核验后处理。账号或结构范围变化，原授权失效。

所有节点身份、类型、父子关系、四表及必要字段核验成功后才启用schema=4连接。已有字段不自动改类型，不覆盖旧表、视图和自动化；字段缺口说明差异后另行授权。新骨架包含兼容业务字段及选题关联，不自动建立现役部署的视图和工作流。Base中“内容库”展示文件夹可按原生工具能力整理，四表以真实ID寻址。

无Python平台依据同一结构清单调用原生工具，保留每个已创建对象的真实ID和核验结果。无法持久化本地状态时，下次从飞书重新发现，不宣称运行过脚本测试或拥有本地队列。

## 第一批只完善核心知识

不用先填满12页。先从[起步访谈](../../assets/templates/knowledge-starter.md)分批共创四类内容：

1. 个人档案：已确认身份、经历和公开边界。
2. 内容目标：当前想服务谁、讲什么、希望发生什么下一步。
3. 受众与需求：真实问题和已有证据；经营者猜测保留待验证。
4. 表达习惯：已确认偏好与失真边界；没有规则就明确零条，不补造风格。

每批先向用户复述理解，展示拟保存的具体文字、位置与候选状态；用户允许后按连接说明保存与回读。昵称只在单独长期记忆授权后保存，不代替账号核验。战役、阶段复盘和私人方法以后按需使用。

## 用一条素材验证理解

接收一份真实素材，先按[共创工作流](../creation/workflow.md)判断本轮是讨论、选题还是出稿，再调用必要的渠道方法。选题与出稿意图分开；生成、确认可发布和真实发表分开。交付一条完整内容后解释保留的用户判断、来源与未知事实，用户确认保存时才入库。

首次成功标准：有来源的核心知识已校准 → 读取相关资料 → 用素材创作一条内容 → 获具体授权后保存并回读 → 新会话按同一账号/空间恢复。骨架ready仅说明结构可用，不代表用户事实已填好或三个平台均通过。

若工具受限，继续基于用户当前素材创作，明确本次未建立长期记忆。不得为测试擅用生产库。离线合成旅程与真实用户效果分别记录。

骨架完成后，个人称呼/协作条目与私人规则按[个人源协议](personal.md)分批校准并保存；没有条目不填假规则，不把骨架成功当个人资料迁移成功。
