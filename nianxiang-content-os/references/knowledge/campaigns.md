# 念响AI · 内容战役管理

## 用途

当活动、直播、课程或产品发售、合作联动、案例发布、系列主题等任务，需要围绕同一目标在有限周期内组织多项内容、多个渠道或战役前中后阶段时使用。

本文件规定Agent如何判断、生成、更新和验收真实内容战役文档。飞书不保存空白标准模板，用户也不需要自行填表。

## 一、文档角色与边界

内容战役文档回答：这场传播为什么做、对谁说、用什么主线、如何在各阶段推进、产生了什么结果、哪些资产值得留下。

不承接：

- 单篇内容的全部改稿过程；
- 已发布作品和数据的长期总账；
- 可跨项目复用观点与案例的完整资产正文；
- 共创讨论的逐轮聊天记录；
- 要求用户从零填写的空白母版。

用户要求作品入库后，单篇完整内容、版本和真实发布结果进入`01｜内容操盘 / 内容中台`对应渠道表；确需独立文档的长正文再由`02｜内容档案`承接。可复用材料经确认后进入`02｜内容资产库`。战役文档通过链接和必要摘要保持项目全貌。

## 二、战役成立门槛

同时满足以下三项才建立内容战役：

1. 有一个明确传播或业务目标；
2. 有可识别的起止周期或关键节点；
3. 需要两项以上内容、两个以上阶段或多渠道协同。

不满足时按普通选题或单篇内容处理。活动本身不自动等于内容战役；没有传播目标和内容协同时，只是事件记录。

## 三、命名、状态与位置

- 父节点：`03｜创作与运营 / 03｜内容战役`。
- 标题：`YYYY-MM-DD｜项目名称｜内容战役`；日期使用主要发生日或启动日。
- 同一战役只维护一份当前项目文档，不按每次修改追加补丁页。
- 状态只使用：筹备中、进行中、待复盘、已完成、已终止。
- 已完成表示发布、必要跟进、复盘和资产分流均已处理，不等于现场活动已经结束。

## 四、固定结构

一级章节依次使用中文序号，不使用`1｜`、`2｜`等阿拉伯数字编号：

### 一、战役档案

记录战役类型、起止时间、负责人、协作方、当前状态和关键链接。系统寻址、token、revision和自动验收状态不进入正文。

### 二、目标与成功标准

区分业务目标、内容目标、目标受众行动、最低成功标准和可验证指标。曝光、咨询、到场、成交等不同层级不得混写成同一种结果。

### 三、事实底稿与公开边界

分开记录已确认事实、待确认事实、资料来源、隐私与合作方边界。未确认数字、效果、身份、承诺或引用不得补写。

### 四、受众与核心表达

说明核心受众、触发场景、真实问题、主要顾虑、一句话核心表达和统一承接动作。一场战役只保留一个主中心，其他观点作为支撑。

### 五、战役故事线

至少说明开场为什么值得关注、展开为什么可信、收束后受众能获得什么并做什么。故事线服务同一核心表达，不按渠道各写一套互相冲突的主线。

### 六、内容作战地图

按真实阶段列出内容任务、渠道或形式、发布时间、负责人、完成证据和状态。活动型任务可用战役前/中/后；发售、系列内容等可使用更合适的阶段名称，不强行套活动流程。

### 七、执行与素材

记录任务责任、素材来源、必须采集或制作的内容、依赖与风险。只加载与战役类型匹配的可选模块。

### 八、发布与跟进记录

记录真实发布渠道、时间、链接、反馈和后续动作。计划发布不得写成已发布，线索不得写成成交。

### 九、结果复盘

对照第二章的目标填写实际结果、有效内容、有效渠道、真实行动、无效投入、被验证或推翻的判断，以及下次调整。

### 十、资产沉淀与归档

列明选题与草稿、发布与数据、可复用观点案例、原始素材各自去向。相同正文只保留一份，其他页面通过链接和摘要关联。

资料不足的固定章节保留`待确认`和最小必要问题，不用通用建议填满；确实不适用的字段可以省略，但不得改变章节职责。

## 五、按战役类型加载可选模块

只加载命中的类型，不创建独立空白模板：

| 战役类型 | 可选模块 |
|---|---|
| 线下活动 / 分享 | 嘉宾分工、现场流程、关键画面与原话、临场发布、活动后跟进 |
| 直播 / 公开课 | 预热节点、直播脚本、互动问题、回放承接、切片计划 |
| 课程 / 产品发售 | 产品事实、用户问题、内容节奏、转化路径、截止节点、销售跟进 |
| 联名 / 合作 | 双方目标、分工、审核权、素材使用权、发布节奏、退出条件 |
| 案例发布 | 案例授权、事实证据、Before/After边界、成果口径、客户隐私 |
| 系列内容 / 主题月 | 栏目主线、选题矩阵、更新频率、渠道适配、一致性检查 |

单人手机拍摄、签到台、现场合影等属于线下活动可选模块，不进入所有战役的固定结构。

## 六、生成与更新流程

1. 先读取用户材料和必要的经营策略、受众、相关资产，冻结已确认事实。
2. 判断是否达到战役门槛，并选择一个主类型；确有混合形态时再增加一个辅助类型。
3. 在对话中先形成目标、核心表达和故事线。用户明确要求建立、生成、归档或更新战役后，才写入战役文档；战役中的具体作品也仅在用户明确要求作品入库、沉淀本次共创或保存具体作品信息时按[内容对象契约](works.md)建档。
4. 实时核对`content.campaigns`映射及父节点标题，在其下创建或定位唯一项目文档。
5. Agent依据固定结构直接生成可执行内容；向用户追问只限会改变真实性、方向或公开边界的最少问题。
6. 更新已有战役时优先原位综合修改，不在文末追加“某日补充”式补丁。
7. 战役中的渠道作品只有在用户明确要求作品入库、沉淀本次共创或保存具体作品信息时才进入内容库对应渠道表；战役文档保留相关作品链接和必要摘要，不复制完整正文。真实发布事实记录在对应作品的实时字段中，不从计划推定。
8. 写后回读并按第八节验收。未通过时继续修正；网络或权限状态不确定时停止写入并只读核验。

## 七、事实与状态门禁

- 区分已确认事实、用户决定、阿响建议、待验证假设和真实结果。
- 计划、建议和候选内容不得升级为已完成；用户确认定稿不等于已经发布。
- 活动现场热度、播放量、点赞和私信只是对应层级信号，不自动代表获客、成交或长期价值。
- 对外案例中的客户名称、数据、原话和图片默认需要公开授权；没有授权时匿名或标记待确认。
- 战役目标可以有商业承接，但不得承诺必然流量、收入、成交率或效果。

## 八、写后验收

完成前必须回读确认：

- 标题、父节点和状态正确，且同一战役没有重复页面；
- 十个一级章节使用`一、二、三……`中文序号，职责没有互相串位；
- 目标、核心表达和承接动作清楚且只有一个主中心；
- 事实、用户决定、阿响建议、待验证假设和真实结果已分开；
- 内容作战地图包含阶段、内容、时间、负责人和完成证据；
- 只加载了匹配战役类型的可选模块；
- 发布计划与真实发布状态没有混淆；
- 复盘指标能回到最初目标；
- 作品档案、Base记录和战役索引相互可追溯，没有把相同正文机械复制到多个页面；
- 文档中没有token、revision、内部knowledge_id或要求用户自行填写的空白模板说明。

任一关键项不满足，视为战役文档未完成。

阶段反馈按[复盘方法](../system/review.md)区分互动/咨询/成交及未知项；未达到战役门槛不另建项目。
