# 念响OS · 知识地图

## 使用边界

念响飞书知识库是内容策略、个人事实、表达基线、内容资产与作品事实的权威来源；渠道写法在包内 creation 模块，共同执行规则在统一入口与工作流，不重复维护。本文件只描述结构，不保存用户专属空间ID、token或私有链接；部署值在私有`<profile>/local-config.json`。每次访问按[本地配置与首次连接](connection.md)核对实时节点、标题、对象类型和父子关系。旧朋友圈系统只在用户明确指定时作为参考。

## 当前结构

```text
01｜定位与策略
├─ 01｜内容经营策略
├─ 02｜受众与需求
├─ 03｜个人IP档案
└─ 04｜个人表达风格

02｜共创与资产
├─ 01｜念响共创记录
└─ 02｜内容资产库（分类入口）
   ├─ 观点库
   └─ 服务案例库
   （故事库、知识库在首次收录时按需创建）

03｜创作与运营
├─ 01｜内容操盘
│  └─ 念响AI · 内容中台（Base）
│     ├─ 选题池
│     └─ 内容库
│        ├─ 朋友圈文案
│        ├─ 短视频口播
│        └─ 公众号长文
├─ 02｜内容档案
│  ├─ 选题地图
│  └─ 渠道作品
│     ├─ 朋友圈
│     ├─ 短视频口播
│     └─ 公众号长文
├─ 03｜内容战役
└─ 04｜阶段复盘

04｜内容方法论（导航入口）
├─ 01｜创作方法与规则
└─ 02｜内容范式库（只作索引与导航，首次有已确认范式且获授权时创建）
   └─ FS三位编号｜范式名称（每条范式均为直属独立子文档）
```

首页与四个板块是同级入口。`01｜内容操盘`是人可读说明；日常选题与作品记录以内容中台Base为准。`内容库`下的三张渠道表分别承接正文版本、关键修改意见及发布数据；旧作品索引若在其他部署仍存在，只作历史兼容；不是新部署必需项，不补建。`02｜内容档案 / 渠道作品`仍可承接需要独立文档的长正文或历史资料，但不为朋友圈与口播机械复制一份文档。用户要求批量初稿文档时放入对应渠道目录；选题地图目录只承载选题地图，不放完整渠道稿。共创讨论默认在对话进行；选题地图按[选题方法](../creation/topics.md#选题地图与文档)优先创建或更新飞书文档并回读，对话给摘要与链接。已连接知识库时在`content.archives`下动态核验唯一精确标题的`选题地图`目录及同批文档，缺失或歧义按连接协议处理；不因默认交付而擅自重建知识库结构。其他稿件按约定载体交付，默认对话全文，明确文档协作时全文进入文档并回读。地图文档交付与选题入池、作品入库分别执行，不因创建地图就写Base或改长期知识。`03｜内容战役`、`04｜阶段复盘`与长期知识仍按各自授权流程使用。

## 映射与权限

| knowledge_id | 对象 | 用途 |
|---|---|---|
| `content.strategy` | 01｜内容经营策略 | 当前目标、表达主线、经营边界 |
| `audience.needs` | 02｜受众与需求 | 人群、场景、问题与证据等级 |
| `ip.profile` | 03｜个人IP档案 | 已确认身份、经历、公开边界 |
| `expression.baseline` | 04｜个人表达风格 | 已确认、跨渠道稳定的个人表达气质、偏好与失真边界 |
| `cocreation.index` | 01｜念响共创记录 | 按需保留有独立价值的共创过程、取舍与待验证认识；不是知识库或Skill更新的前置；结构与排版按[共创记录契约](co-creation-records.md)；创建型父节点 |
| `content.assets` | 02｜内容资产库 | 分类导航与收录说明；观点、服务及本人实践案例、故事、知识分别保存在直属分类文档，按[资产分类与收录](assets.md)查找与维护 |
| `operations.index` | 01｜内容操盘 | 内容生命周期的人可读入口 |
| `operations.base` | 念响AI · 内容中台 | Base对象，含选题池与朋友圈、短视频口播、公众号长文三张正式作品表 |
| `content.archives` | 02｜内容档案 | 选题地图与渠道作品目录的父节点 |
| `content.campaigns` | 03｜内容战役 | 真实战役文档的创建型父节点 |
| `content.reviews` | 04｜阶段复盘 | 真实复盘文档的创建型父节点 |
| `methodology.current` | 04｜内容方法论 | 只维护导航和使用说明，不维护方法正文或私人规则机器段 |
| `content.methods` | 01｜创作方法与规则 | 方法正文、私人规则与不适用边界；直属于内容方法论，私人规则机器段唯一源 |

## 最小读取策略

1. 实质共创按需从显式选定配置档读取`content.strategy`和`expression.baseline`；同任务有效上下文及版本沿用。新任务按[缓存协议](../system/synchronization.md)核验相关源版本，未变复用缓存正文；换平台明确选择该环境profile。上下文包位置为`<profile>/snapshots/context.json`，单页JSON是兼容镜像，不在Skill内存个人正文。个人IP与受众只在本篇依赖相应事实或边界时读取。本地副本保留核验日期，不假称本轮最新；网络失败可用未失效的可信副本继续普通创作，明确要求最新或已知关键冲突时核验所需页。没有连接时使用本轮素材，不编造个人风格。
2. 用户找选题时查选题池；找待发布或已发布作品时按渠道查内容库对应表的作品键、标题、关联选题、版本与发表状态。仅在实际存在旧索引且需要追溯时读取，不把它当当前入口。
3. 寻找可复用证据时按[资产分类与收录](assets.md)先定位相关分类文档，再读命中的资产；需要细节时追溯对应来源。追溯无作品认识时只读命中的共创记录。
4. 围绕具体战役时只读相关战役；判断阶段效果时只读相关复盘。
5. 需要方法或私人规则时读取`content.methods`，按范围与成熟度筛选；找具体表达、结构或视觉范式时按[分类协议](assets.md)从`methodology.current`动态发现`02｜内容范式库`。每条范式同时检查父索引和库下子文档，核验来源与父节点；导航页或摘要链接不能代替实际归档，单篇范式不能直接升级为稳定方法。

上述最小读取策略适用于日常共创。用户要求依据经营蓝图评估或更新《内容经营策略》时，按[策略维护闭环](strategy.md)核对最新上游蓝图，并检查《受众与需求》的受影响内容；不能因日常创作通常不读受众页，就跳过本次策略维护的关联核查。

## 失效处理

节点缺失、同名、类型或父子关系不符时停止对应写入。先只读定位并报告差异，不用相似标题猜目标。文档事实与本轮输入冲突时展示旧值、新值和证据；由用户决定。写入渠道作品时按[内容对象契约](works.md)查重与回读，不能因网络不确定重复创建。

结构化称呼/协作复用`ip.profile`，私人规则唯一源为`content.methods`，字段、投影与显式迁移见[个人源协议](personal.md)。服务案例与内容范式子库按父节点、同空间、唯一精确标题和token配对动态发现，不为每个子库增加固定映射。
