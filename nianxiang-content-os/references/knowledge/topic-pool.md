# 念响OS · 选题入池与找回

## 何时使用

当共创出现值得以后再写的选题、用户要求`选题入池`或找回旧选题，或用户要求把已入池选题与作品关联时读取。选题池位于念响知识库`03｜创作与运营 / 01｜内容操盘 / 内容中台` Base；只承载可找回的待写线索，不保存过程稿。

## 1. 提议与授权

只有选题能独立继续、有清楚的一句话切口，并有真实素材或明确受众需求支撑时，才在合适的收口点说明建议保留的具体选题及价值。不把普通标题备选、泛泛方向或每轮讨论都送入池。若用户眼下要直接创作，先继续创作，不让存题确认打断流程。

阿响的提议不是写入授权。文档勾选若此前已明确约定用于入池，用户说“我选好了”后回读指定地图的最新状态，按所选条目保存；未约定时勾选仅代表选择，不自动写入。不同地图的短编号结合文档与来源定位，不当作全库唯一编号。除上述已约定的勾选入池外，只有用户明确说`选题入池`、“留着”“下次写这个”“把第2条收起来”等，才保存所指条目；多条候选时仅保存用户选中的条目。单说“入池”且可能指作品时先澄清；指代不清也不猜。用户不回应或拒绝时只留在对话，不反复催促。明确“这次不保存”同时阻止本轮选题入池。

## 2. 一张轻量选题卡

`选题池`字段：`选题`、`选题编号`、`选题键`、`一句话切口`、`价值依据`、`来源线索`、`来源链接`、`当前状态`、`朋友圈文案作品`、`短视频口播作品`、`公众号长文作品`（各渠道反向关联）、`入池时间`。只写必要事实，未知字段留空；不复制聊天、提纲、局部稿或未经确认的经历。`来源线索`写能帮助下次找回的简短主题、场景或日期；有可访问的共创记录或原始材料链接时才写`来源链接`。系统创建时间不传写。地图入池时可按需要在既有价值依据、来源线索中保留现场与判断，不复制渠道稿。`来源链接`可指向选题地图的具体题目块，超链接显示中文主题与地图短编号（如 `[需求访谈选题地图｜A1](https://example.com/topic-map#REPLACE_WITH_BLOCK_ID)`），而非把网址当显示标题；已有来源字段能够定位时不另建同义字段。

状态初始为`待创作`，后续只能是`待创作`、`已成稿`、`暂缓`、`放弃`。这些是选题状态，不等于作品的发表状态。`选题键`用于幂等：能取得稳定对话ID时用`nxt:<对话ID>:<本轮选题序号>`；否则首次确认保存时生成UUID并在本轮记住。跨会话重提旧题时先检索已有记录，以切口与来源核对；不能只凭同名标题自动合并。

写入前按已知`选题键`查重，并按标题、切口、来源线索检索可能的旧记录。唯一匹配则沿用或按用户明确要求更新；多条相似且无法确定时先问，不新建。网络结果不确定时先读回，再决定是否重试。写后回读`选题`、`一句话切口`、`当前状态`和来源，确认一致后才告知已保存。

## 3. 找回并继续

用户按主题、素材、时间或“有哪些待写选题”查找时，先检索选题池，优先展示`待创作`项的标题、一句话切口、价值依据及来源线索；需要时再看`暂缓`或`已成稿`。存在同名或近似项时给可辨认的区别，让用户选定。找回后继续内容共创，不强制创建共创记录，也不把选题卡当作品档案。没有匹配时如实说明，并可在用户授权范围内再查相关共创记录。

## 4. 从选题到渠道作品

完整稿按约定在对话或共创文档中交付，不因出稿、定稿或口头告知发布而自动入库。用户明确要求`作品入库`、`沉淀本次共创`或明确保存指令时，按[渠道作品契约](works.md)创建或更新对应渠道表的一条作品记录，并用`关联选题`指向本选题；若尚无可确认的选题，允许作品先无关联，不强造题卡。一个选题可对应朋友圈、短视频口播、公众号长文等多件作品，新增渠道不能覆盖已有关系。

`已成稿`只说明已有稿件，不推定已发表。当前选题均为正式数据，今后不创建演示题卡。写后回读选题关系和渠道作品记录，部分失败不得重复创建。

## 公共管理入口

有Python与用户身份CLI时，按[连接说明](connection.md#授权保存与恢复)使用统一knowledge save与reconcile接口，operation_id绑定原请求，Base以作品键/选题键查重。先读实时字段与对象版本，只精准更新授权字段；saved之外分别报告pending、uncertain、conflict或blocked。原生工具遵守相同业务契约与回读标准，不宣称具备脚本队列或分布式并发保证。
