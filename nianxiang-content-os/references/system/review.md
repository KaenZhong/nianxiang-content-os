# 念响OS · 复盘与下一轮

复盘以已确认目标、用户实际采用/发布版本、可核验反馈为输入。先读相关作品和必要策略，再区分观察、未知项、原因假设与调整候选；不因一次高低数据改长期规律。

## 证据与判断

1. 核对作品键、版本、实际发布状态、渠道及反馈来源/时间。没有真实发布信息时复盘共创过程，注明效果未知。
2. 播放/阅读、点赞/评论、私信/咨询、成交分开陈述。仅互动数据不能推出咨询或成交；时间、数字、归因缺失时列未知项，不补造结果。
3. 比较目标与实际观察，给出具体调整候选及验证方式，例如下一篇保留同一观点、改变开头现场；说明是试行，不包装成已验证规律。
4. 下一步可进入策略、选题、创作或运营，带来源、确认切口、公开边界与真实承接，避免只交一个标题。任务checkpoint可记录已确认下一步，不复制全篇反馈。

## 采用、保存与归属

用户认可候选不自动等于已修改知识或发布。策略/表达/私人规则的具体写入分别获授权、读取最新目标并回读；没有授权只展示候选，源保持原样。个人方法归[飞书私人源](../knowledge/personal.md)，单篇取舍归[作品](../knowledge/works.md)，独立决策按[共创记录](../knowledge/co-creation-records.md)归档。多阶段有限周期项目达到门槛才建立[战役](../knowledge/campaigns.md)。

共创收口仍用[共创工作流](../creation/workflow.md)八项扫描：第八项只探测非念响独立创作Skill，不创建、改写或发布。念响自身路由、人格或工具问题记为版本维护反馈。反馈没有独立价值时无需凑Skill候选。

隔离合成旅程证明保存/恢复/版本及边界的代码行为；真实表达质量、实际平台交互与用户经营效果必须单独检查，不能由代码断言证明。
