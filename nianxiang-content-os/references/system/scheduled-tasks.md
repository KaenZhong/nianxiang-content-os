# 念响OS · 定时协作引导

## 触发与时机

主口令为`设置定时任务`；“每天帮我推荐朋友圈”“每周一准备选题”等自然语言同义表达进入同一引导。`调整定时任务`维护已有设置，`暂停定时任务`和`恢复定时任务`控制已有任务。询问口令、引用、否定或模拟不创建任务。

优先在用户完成一次真实共创、希望持续发布时引导，不在首次安装时强推设置。读取已有有效决定，避免重复询问时间、渠道及目标。

## 选择任务交付

- **选题推荐**：候选选题、推荐理由与来源，适合愿意继续讨论、自己创作的用户。
- **已有稿件推荐＋工作台（推荐）**：从内容库挑选已有稿件，将完整正文、标题候选、已有配图、原始来源及推荐理由装入多稿工作台，适合积累了初稿但卡在采用与发布的用户。
- **每日内容准备**：基于明确素材准备初稿并装入工作台；须有生成完整稿的明确授权、足够事实和公开边界。开设选题推荐任务不自动授权生成或改写正文。

任务名称按业务命名，例如“每日朋友圈准备”；不把频率、数量、发布时段或某个经营者的作息写成公共默认。

## 设置流程

1. **真实演示。** 使用用户选定范围内的真实材料，先展示一次推荐消息及已装入稿件的工作台；演示不假装到时触发，也不改变原作品状态。
2. **补齐必要选择。** 确定目标、主要受众、渠道、准备时间与时区、频率与篇数、素材来源、缺稿处理及交付位置；已知值沿用，只补决定性缺口。一个作品只服务主要受众并保留真实承接。
3. **核验宿主能力。** 检查当前平台实际提供的定时任务、知识读取、文件持久性、页面生成及打开能力。优先更新同目标已有任务；豆包、Codex等由各自正式工具创建或调整，不猜接口、不用另一平台任务冒充原平台接通。
4. **展示具体配置再执行。** 给任务名称、触发时间及用户时区、读取范围、允许的生成/修改、交付结果、失败处理与暂停恢复方式，用户确认后通过宿主正式能力创建并回读。概括性讨论不等于创建授权。无可用工具时交付可复制配置并说明尚未设置。
5. **立即试跑及首次运行验收。** 检查读取、版本选择、查重范围、稿件载入、来源、复制与交接。立即试跑成功不证明首次定时触发成功；到时运行结果另核验，不自行宣称后台长期可用。

## 每次运行与版本判断

先实际取日期及用户时区，按当前已确认经营目标读取实时作品及关联选题，查重并按价值型、信任型等已定用途选稿。频率与类型随用户决定，不固定“2＋1”。无新现场素材不凑存在型。

`发表状态=待发布`不等于已经可发布。正文优先使用用户指定版本；未指定时：已发布作品仅在用户要求参考或复用时取实际发布版，其他取有效待发布版，其为空时可载入第一版并标“初稿待校准”。不把第一版补成待发布版、不擅自选定候选标题，也不把预览算作采用或发布。适合直接使用的稿不强制压成固定字数；缺用户事实、判断或公开许可时列明缺口，不编造后填。

核对近期实际发布记录与重复推荐线索；覆盖不足说明实际范围。内容库没有新增发布记录只支持“未见新增记录”，不能断言用户没有发布、指责拖延或据此自行暂停任务。重复未采用时可提出调整建议，暂停及频率变化仍须用户确认。

## 对话与工作台交付

对话给当天日期、推荐篇数、每篇用途/标题/简短理由/真实状态和一个主要工作台入口。完整正文、候选标题、已有配图、原始稿件及选题来源在工作台；缺失字段如实标记，不能用作品链接冒充选题材料。多篇已确定时默认打开推荐顺序第一篇；保留用户同批的本机编辑与阅读位置。

生成并核验实际页面后才能说“已放入工作台”。打开能力可用时优先复用已有页面；自动弹出、可点击入口、跨设备访问分别验收。只有本机地址时说明设备限制，不能向豆包云端提供另一设备的localhost并声称可用。原始链接能直达篇章时保留锚点，未检查不能说已验证。

消息示意仅用于结构：日期 → 两篇标题、用途、推荐理由及初稿/可发布状态 → 实际工作台链接 → 必要时间提醒与查重覆盖。无需让用户再次回复编号才能看到已选稿。已错过时段按实际时间说明，不照搬早晨提醒；微信由用户手动发布，不宣称支持定时发布。

读取失败、缺稿或页面生成失败时说明具体缺口与已完成范围，给可访问原稿或对话全文降级，不发送空白模板假装成功。不得因模板缺失生成虚构例稿代替真实输出。

## 维护与边界

调整目标或受众后检查原任务是否仍适用，先显示具体差异，确认后更新；暂停保留原配置及原因，恢复先刷新目标、材料与交付位置。确认定时任务不等于授权微信发送、作品入库、发布回填或长期知识更改；分别沿作品与知识契约办理。

多稿页面只承接已有稿件供编辑，不提供手动添加稿件入口。生成和装入不改变飞书正文；页面编辑留本机，用户交回并明确保存范围后才处理原作品。定时任务配置、个人时间及真实稿件留宿主或私人目录，公共Skill仅维护通用引导。
